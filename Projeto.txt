# API REST para Gerenciamento de Reservas de Salas

## Descrição do Projeto

Neste desafio, será desenvolvida uma API REST para gerenciamento de reservas de salas utilizando Java com Spring Boot, aplicando conceitos fundamentais de desenvolvimento back-end, arquitetura em camadas, persistência de dados, testes automatizados e boas práticas de engenharia de software.

O projeto tem como objetivo consolidar conhecimentos relacionados a:

- Programação Orientada a Objetos (POO)
- Desenvolvimento de APIs REST CRUD
- Persistência de dados com Spring Data JPA
- Regras de negócio e validações
- Arquitetura em camadas
- Testes unitários
- Versionamento com Git e GitHub
- Containerização com Docker

A aplicação permitirá o gerenciamento de:

- Salas
- Usuários
- Reservas

Além disso, o sistema deverá garantir regras essenciais como prevenção de conflitos de horários, controle de status de reservas e validações de domínio.

# 3. Modelagem do Domínio

Representa uma sala disponível para reservas.

#### Atributos sugeridos

* capacidade
* ativa

#### Responsabilidades

* Armazenar informações da sala
* Validar capacidade
* Informar disponibilidade

---

### Usuario

Representa um usuário do sistema.

#### Atributos sugeridos

* id
* nome
* email

#### Responsabilidades

* Identificar o responsável pela reserva
* Manter dados cadastrais

---

### Reserva

Representa uma reserva realizada em uma sala.

#### Atributos sugeridos

* id

#### Responsabilidades

* Controlar horários
* Validar conflitos
* Gerenciar cancelamentos

# 5. Regras de Negócio

## Validações Obrigatórias

### Sala

* Capacidade deve ser maior que zero
* Sala inativa não pode receber reservas

### Reserva

* Data inicial deve ser anterior à data final
* Não permitir reservas sobrepostas
* Reservas canceladas não entram em conflito

---

# 6. Regra de Conflito de Horários

## Política de Intervalo

Será utilizado intervalo semiaberto:

```text
[início, fim)
```

Isso significa:

* O horário inicial é incluído
* O horário final não é incluído

---

## Exemplos

| Reserva A     | Reserva B     | Resultado |
| ------------- | ------------- | --------- |
| 10:00 - 11:00 | 11:00 - 12:00 | Permitido |
| 10:00 - 11:00 | 10:30 - 11:30 | Conflito  |
| 10:00 - 11:00 | 09:00 - 10:00 | Permitido |

---

# 7. Status da Reserva

## Enumeração de Status

```java
public enum StatusReserva {
    ATIVA,
    CANCELADA
}
```

---

## Regras

### Reserva Ativa

* Participa da validação de conflito
* Pode ser cancelada

### Reserva Cancelada

* Não participa da validação de conflito
* Permanece registrada no histórico

# 9. Endpoints da API

## Sala

| Método | Endpoint    | Descrição      |
| ------ | ----------- | -------------- |
| GET    | /salas      | Listar salas   |
| GET    | /salas/{id} | Buscar sala    |
| POST   | /salas      | Criar sala     |
| PUT    | /salas/{id} | Atualizar sala |
| DELETE | /salas/{id} | Remover sala   |

---

## Usuario

| Método | Endpoint       | Descrição         |
| ------ | -------------- | ----------------- |
| GET    | /usuarios      | Listar usuários   |
| GET    | /usuarios/{id} | Buscar usuário    |
| POST   | /usuarios      | Criar usuário     |
| PUT    | /usuarios/{id} | Atualizar usuário |
| DELETE | /usuarios/{id} | Remover usuário   |

---

## Reserva

| Método | Endpoint                | Descrição         |
| ------ | ----------------------- | ----------------- |
| GET    | /reservas               | Listar reservas   |
| GET    | /reservas/{id}          | Buscar reserva    |
| POST   | /reservas               | Criar reserva     |
| PUT    | /reservas/{id}          | Atualizar reserva |
| PATCH  | /reservas/{id}/cancelar | Cancelar reserva  |
